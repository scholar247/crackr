Best approach for high-throughput distributed rate limiting?

I'm currently designing an API gateway that needs to handle approximately 50,000 req/sec peak. We need a rate limiter that is accurate but doesn't add more than 5ms latency to the critical path.

We've considered Redis with Lua scripts (Token Bucket), but I'm worried about the single-node bottleneck and the overhead of network hops. Has anyone successfully implemented a sliding window log approach at this scale without sacrificing latency?

// Current rudimentary approach
public boolean allowRequest(String userId) {

    Long current = redisTemplate.opsForValue().increment(key);
    if (current == 1) {
        redisTemplate.expire(key, 1, TimeUnit.SECONDS);
    }
    return current <= MAX_REQUESTS_PER_SECOND;
}

At 50k RPS, the naive Redis increment approach will choke on network IO. You need to move the rate limiting logic closer to the edge or use a local cache combined with a distributed sync mechanism.

Look into the Leaky Bucket algorithm implemented via Redis Cell module, or if you want sliding window without the huge memory footprint, Sliding Window Counter is a good compromise.
